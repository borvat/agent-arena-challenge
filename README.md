# Agent Arena — autonomous six-agent trading company

A reproducible multi-agent business simulation: six LLM-backed agents run a $100,000 import/trading
company for 90 business days against a deterministic, event-driven market engine, side by side with a
rule-based baseline company that faces the exact same market and seed.

The point of the project is not the dashboard. It is the separation:

| Layer | Who owns it | What it may do |
|---|---|---|
| Decision layer | 4 operating agents + auditor + CEO (LLM, DeepSeek) | Propose typed actions only |
| Policy layer | deterministic gate (`src/world.js#gate`) | Refuse out-of-policy proposals |
| Execution layer | simulation engine (double-entry ledger) | The single writer of money, stock, history |
| Evaluation layer | `scripts/evaluate.js` | Runs both companies under identical seeds |

Agents cannot set a balance, invent inventory, or see a future event. A refused proposal is a first-class
outcome, recorded in the audit log, not smoothed away.

## Run it

```bash
npm install            # installs the Playwright test runner only; the app itself has zero dependencies
cp .env.example .env   # put DEEPSEEK_API_KEY in .env (or export it) — only needed for AI-agent mode
npm start              # http://localhost:4000
```

Useful environment variables:

| Variable | Default | Meaning |
|---|---|---|
| `PORT` | 4000 | HTTP port |
| `DEEPSEEK_API_KEY` | — | model credential; without it the AI company runs on its deterministic fallbacks |
| `AGENT_MODEL` | `deepseek-flash` | model name |
| `AGENT_THINKING` | `off` | `on` enables reasoning tokens (slower, richer, ~5x cost) |
| `AGENT_TIMEOUT_MS` | 45000 | per-call timeout |
| `DISABLE_LLM` | — | `1` forces fallback policies, used by tests and CI |
| `SPEED_MS` | 120 | delay between simulated days in the live UI |
| `DATA_DIR` | `./data` | run snapshots + audit logs |

```bash
npm test                       # 35 unit/integration tests (node:test)
npm run test:e2e               # 6 Playwright browser tests against the real server
node scripts/verify.js         # 23-check local verification gate
node scripts/evaluate.js       # baseline vs agents, 3 seeded scenarios + 1 held-out
node scripts/failure-recovery.js
```

## The market engine

`src/scenarios.js` defines four products (earbuds, smartwatch, USB-C hub, speaker), four suppliers with
different reliability, lead time and price index, and three seeded scenarios:

| Scenario | Difficulty | Character |
|---|---|---|
| `steady-growth` | easy | stable demand, cooperative suppliers |
| `supply-shock` | medium | supplier price spikes, freight delays, a port strike |
| `liquidity-crunch` | hard | demand collapse, late-paying customers, competitor price war |
| `heldout-*` | unseen | generated by the evaluator at run time from a fresh seed |

Each day the engine: activates seeded events, drifts competitor prices, receives purchase orders (paying
cash on arrival), computes demand from price elasticity/events/promos/credit terms, books sales
(revenue + COGS at the point of sale), collects receivables, charges rent, salaries and storage, then
asserts its invariants.

Determinism: every random draw comes from a named seeded stream (`src/rng.js`), and nothing reads the
wall clock. Two runs with the same seed and the same action sequence produce an identical fingerprint.

Accounting invariants checked every simulated day (a violation halts the run, it is never averaged away):

- every ledger entry balances to the cent,
- inventory, cash and equity stay finite and non-negative,
- the balance sheet closes: `cash + inventory + receivables = capital + revenue - COGS - opex`.

## The six agents

| Agent | Levers | Mandate |
|---|---|---|
| CEO Agent | `CAP_SPEND`, price override, approvals | capital allocation, arbitration, solvency |
| Procurement Agent | `PROCURE`, `NEGOTIATE` | landed cost vs lead time vs reliability |
| Sales Agent | `SET_PRICE`, `PROMO` | contribution margin, not revenue |
| Finance Agent | `CREDIT_TERMS` | liquidity, cash runway, receivables |
| Logistics Agent | `EXPEDITE` | stock cover vs inbound ETA |
| Auditor Agent | veto only | independent policy and integrity review |

One decision cycle (every 5 days, plus an off-cadence cycle whenever a material market event fires):

1. Procurement, Sales, Logistics and Finance propose **in parallel**.
2. The Auditor reviews every proposal and may veto with a rule reference (veto is binding).
3. The CEO arbitrates: approves/rejects by proposal id, sets the strategy line, may adjust price or spend caps.
4. The engine's policy gate re-checks each action; approvals above threshold are required for orders over
   $8,000, price moves over 15%, and promos over $500.
5. Executed and refused actions are recorded with the agent, rationale, latency, token usage and cost.

Organisational memory (`src/memory.js`) keeps decisions and lessons, retrieved per role by a deterministic
lexical + recency + importance score, so later prompts carry the company's own history.

### Real model decisions vs deterministic logic

Every agent turn is tagged `source: 'llm' | 'fallback'`. Fallbacks are rule-based (reorder under-covered
SKUs, cost-plus pricing, credit terms from runway) and exist so a provider outage degrades the run instead
of killing it. The UI shows the tag on each agent card; `data/eval-report.json` counts them.

## Command centre

Arabic-first RTL UI with an English toggle, served from `public/` with no framework and no build step:

- equity/cash chart over the simulated days, KPI strip, P&L and cash-flow figures derived from the ledger
- live agent cards (last analysis, source tag, latency), decision timeline with executed/refused/vetoed pills
- inventory cover, competitor prices, supplier quotes and negotiation windows, purchase-order ETAs
- policy limits, active market events, audit log streamed over SSE
- start / pause / resume / single-step / reset controls, scenario and mode selectors
- run history and the evaluation comparison table

## Evaluation

`scripts/evaluate.js` runs the baseline and the agent company per scenario with identical seeds, cadence,
capital, policy and action vocabulary. Baseline decisions are fixed rules; it cannot negotiate, cannot run
a promotion and has no memory. Model calls, tokens and cost are recorded per agent.

Full results, cost report, security results and the honest verdict: **[docs/EVIDENCE.md](docs/EVIDENCE.md)**.

## Security posture

- the model credential is read from the environment; it is never sent to the browser, never logged, and
  error strings are redacted before they reach the audit trail
- no HTTP route accepts a balance, stock, price or ledger mutation: `POST/PUT/PATCH/DELETE` on a run
  returns `403` with an explanation, and only typed proposals reach the engine
- strict CSP, `nosniff`, frame-deny, `no-referrer`, 64 KB body cap, per-IP rate limiting
- static file serving is normalised and confined to `public/`

## Limits (stated, not hidden)

- The baseline is strong on a benign market: it targets 28 days of cover and prices cost-plus, which is
  hard to beat on `steady-growth`. The agents win on margin, not on equity.
- One model provider, one model family. No fine-tuning, no retrieval beyond organisational memory.
- The engine is a stylised market: no taxes, no multi-currency, no supplier credit, one warehouse.
- LLM decisions are sampled (temperature 0.3), so scenario results vary slightly between runs. The engine
  given a decision sequence is exact; the decision sequence is not fixed.
